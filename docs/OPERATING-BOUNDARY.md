# GREENY-LIFE Operating Boundary

## Runtime authority

Greeny-Life-Repair is the sole development and operating workspace for the rebuilt GREENY-LIFE system. Its Next.js application, PostgreSQL schema, protected APIs, governed workflows, and local operating brains are the active runtime candidate.

## Legacy boundary

Legacy material inside this repository, including archive, canonical, intelligence, brain.py, greenlines_brain, eos-core, application, domain, database, and governance, is retained as evidence, knowledge, migration input, capability source, and comparison baseline. It is not an executable authority and must not receive new operational changes.

## Rules

1. No legacy file is deleted, overwritten, relocated, or bulk-cleaned without a reviewed retention decision.
2. No legacy automation runs against live data unless it passes current evidence, approval, and runtime gates.
3. A capability is retired only after owner, consumers, data dependencies, replacement, test evidence, and retention path are recorded.
4. The new system remains a candidate until the Final Engineering Gate is independently verified.
5. Any gap found in legacy is a migration or reconnection candidate, never permission to copy unsafe behavior.

## Completion conditions

- Capability conservation review complete.
- Legacy runtime entrypoints classified and quarantined where unproven.
- PostgreSQL master-data reconciliation complete.
- Security, evidence, authority, workflow, and learning gates verified.
- Controlled end-to-end export scenario tested.
- Final Engineering Gate returns APPROVED; otherwise replacement remains BLOCKED or PARTIAL.
