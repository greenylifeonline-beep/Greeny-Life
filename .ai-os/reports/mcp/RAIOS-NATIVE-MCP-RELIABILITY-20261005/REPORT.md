## 1. جاهزية النفق الأصلي

الملف: `scripts/runtime/Start-RAIOS-Native-MCP-System.ps1`.

- أُزيل الشرط القديم الذي يقبل ثماني أدوات.
- دالة الجاهزية تتحقق من أسماء الأدوات التسع المطلوبة، بما فيها `execute_scoped_task`، ومن مطابقة العدد المعلن للقائمة الفعلية.
- ترفض الأدوات المكررة أو البديلة أو أسماء الأدوات التي تختلف في حالة الأحرف.
- تتحقق من هوية الخدمة، ونقل Streamable HTTP، وقناة الجلسات وSSE، وعدم وجود بوابة ثانية أو اعتماد على Desktop Commander المستضاف.
- ترفض قيم Boolean أو الأعداد المرسلة كسلاسل، والحقول الناقصة والأعطال، بدل اعتبارها جاهزية.
- اختبارات PowerShell تستخرج الدالة الفعلية من AST وتنفذها، دون بدء النفق أو قراءة الأسرار أو تغيير إعدادات الجهاز.

## 2. حدود تنفيذ Git

الملف: `scripts/ai-os/raios_mcp/gateway.py`.

- جميع استدعاءات Git في البوابة تستخدم مهلة خمس ثوانٍ لكل استدعاء.
- انتهاء المهلة ينتج `GIT_TIMEOUT`، وفشل الأمر ينتج `GIT_FAILED`، وتعذر بدء Git ينتج `GIT_UNAVAILABLE`.
- لا يتحول فشل Git إلى بيانات HEAD فارغة مع إيصال نجاح.
- `subprocess.run` ينهي العملية المباشرة وينتظرها عند انتهاء المهلة. الاختبار يشغّل عملية حقيقية معلّقة ويثبت أنها لا تواصل تنفيذها بعد انتهاء المهلة.
- `get_head` يستدعي Git مرتين على التوالي؛ حد انتظار عمليتيه يصل إلى عشر ثوانٍ، إضافة إلى القراءة والتدقيق المحليين. هذا ليس حدًا زمنيًا شاملًا لكل عمليات الملفات أو أحفاد العمليات.
- مسار `/health` السريع يبقى معتمدًا على ملفات Git ولا ينشئ عملية Git.
- اختبار نجاح `get_head` يستخدم مستودعًا حقيقيًا ويقارن SHA واسم الفرع بالقيم الفعلية.

## 3. ردود MCP عند فشل التنفيذ أو التدقيق

الملفان: `scripts/ai-os/raios_mcp/server.py` و`gateway.py`.

- حد معالجة مشترك لـ HTTP وstdio يحتوي الاستثناءات العادية أثناء توجيه RPC والتنفيذ.
- أخطاء الأدوات المتوقعة تبقى نتائج أدوات مع `isError=true`؛ الأخطاء غير المتوقعة في الأدوات تنتج `INTERNAL_ERROR`، وأخطاء التوجيه/المصادقة الداخلية تنتج JSON-RPC `-32603` منظّمًا.
- فشل سجل التدقيق ينتج `AUDIT_UNAVAILABLE` ولا يسمح بإيصال نجاح. كتابة التدقيق لا تُعاد تلقائيًا ولا تعيد تنفيذ الأداة.
- إذا اكتملت الكتابة ثم فشل التدقيق، لا ندّعي التراجع عن أثرها. الرد يطلب مطابقة نتائج الكتابة قبل إعادة المحاولة؛ اختبار فعلي يثبت تسجيل رأي وحزمة واحدة فقط.
- التشخيص يربط الرد بمعرّف `error_id` ونوع الاستثناء في stderr، دون نص الاستثناء أو الرموز السرية أو محتوى الملفات أو معاملات الطلب.
- تعطل مخرج التشخيص نفسه لا يمنع رد الخطأ.
- تُرفض أشكال RPC ومعاملات الأدوات غير الصحيحة بردود منظّمة، ويُحتوى UTF-8 غير الصحيح في مدخل HTTP.
- اختبارات HTTP تثبت أن الجلسة نفسها تستمر بعد الخطأ، للردود JSON وSSE. اختبار stdio يثبت أن طلب ping ينجح بعد فشل تدقيق أداة في العملية نفسها.

## إخفاقات قديمة وحدود التحقق

- `raios_mcp_check.py` يفشل عند `C1 role matches seat map` على المصدر الأصلي والمعدل. سياسة البوابة وخريطة المقاعد غير متطابقتين في النسخة الأساسية؛ لا تتضمن هذه المهمة تغيير سلطات المقاعد.
- `raios_mcp_security_check.py` يفشل عند إيصال `GL005-MUTATION-OBSERVE.json` غير الموجود في نسخة المصدر. ظهر الفشل نفسه قبل الإصلاح وبعده.
- مجموعة `tests/command_center` تعذر جمعها: FastAPI غير مثبت في بيئة الاختبار المركزة، ووحدة `raios.command_center.storage_authority` غير موجودة في نسخة المصدر. لم يُدّع نجاح هذه المجموعة.
- جرى تنفيذ اختبار PowerShell على إصدار 7.5.3 في Linux. راجعت المراجعة توافق الصياغة مع Windows PowerShell 5.1، لكن التنفيذ على Windows لم يتم.
- اختبار إيقاف العملية يثبت إنهاء الطفل المباشر، وليس شجرة عمليات كاملة. لا يدّعي التقرير ضمانًا ضد كل عطل مستقبلي أو كل مشكلة في النفق الخارجي.
