# سجل ترقية المصدر والتكوين

نُفّذت الترقية في فرع معزول دون تغيير خدمة Windows الحية أو حذف تعديل أو إيصال.

## ما تغير

- استخدام حزمة MCP الرسمية MIT بإصدار مثبت 1.30.0 داخل مزوّد Desktop Commander المحلي الموجود. بقي خادم RAIOS القناة الوحيدة.
- كل استدعاء يملك جلسة stdio وعملية مستقلة؛ مهلة البدء والاكتشاف والتنفيذ مشتركة، ودخول المزوّد محدود. لا تبقى جلسة تالفة لتحجب الاستدعاء التالي.
- تصدير مخططات MCP ومخططات function calling من الأدوات المكتشفة والمسموحة، والتحقق من الوسائط في عملية مستقلة قابلة للإلغاء.
- حدّ رسائل المزوّد قبل التحليل، وحدّ إجمالي بيانات الاكتشاف والأسماء والصفحات. لا تُسجل محتويات الرسائل التالفة أو stderr أو أخطاء الأداة.
- سكربتا التشغيل يستخدمان Readiness.ps1 والسياسة نفسها؛ أزيل العدد الثابت من فحص الجاهزية. الخادم يرفض اختلاف السياسة والتسجيل.
- تصحيح الفرع، واستخدام هوية المقاعد المعتمدة دون توسيع الصلاحيات. HEAD يُقرأ من Git الفعلي بما فيه worktrees، ولا يستبدله متغير بيئة قديم.
- مهلة مطلقة لجسم HTTP الجزئي، ورفض الطلب الكبير دون انتظار جسمه. الصحة تميز وجود مسار التنفيذ عن إثبات جاهزية مزوّده.

## الدليل

79 اختبار MCP ناجحًا دون تخطي، و83 اختبارًا في مجموعة المشروع الافتراضية ناجحًا. نجح فحص الاعتماديات وتجميع Python وفحص الفروق. اختبارات PowerShell نفذت على 7.5.3/Linux؛ هذا ليس إثبات Windows PowerShell 5.1.

أُثبت استدعاء وظيفة عبر عميل MCP الرسمي وStreamable HTTP إلى RAIOS ثم إلى عملية stdio فعلية. المزوّد المستخدم في الاختبار برنامج Python مضبوط للاختبار، وليس برنامج Desktop Commander Node الموجود على جهاز المستخدم. ثبت رفض الكتابة غير المفعلة والتعافي من التعليق والحجب وإطار تالف أو كبير والتحقق المكلف من المخطط.

المراجعة المستقلة وجدت أربع ملاحظات مهمة؛ أعيد إنتاجها باختبارات فاشلة ثم أصلحت، وأعيد تشغيل المجموعات كاملة. سجل الأدلة في VALIDATION.json والملفات المرفقة.

## الوضع الحالي وما لم يثبت

المهمة الكاملة BLOCKED رغم تحقق المصدر: نسخة Windows الملتزمة وغير المنشورة لم تُستخرج، وموصل الجهاز المستضاف أبلغ نفاد الحصة، والقناة الحية لا تعرض أداة تنفيذ. لم يُثبت نشر هذا التغيير أو تشغيل المزوّد المملوك أو كل الأدوات على Windows. لم تثبت الكتابة المحمية بlease ونطاق وidempotency، ولذلك بقيت الكتابة العامة وshell مغلقتين.

لا توجد مطالبة بضمان عدم تعطل أي أداة مستقبلًا أو اجتياز كل حالات الإغراق وSSE. توجد حدود واختبارات محددة وأخطاء منظمة؛ التحقق المحلي يبقى شرطًا قبل إعلان الجاهزية الكاملة.

## الاعتماديات والتفعيل

المزوّد يحتاج Python >=3.10 وملف requirements.txt المثبت؛ requirements.lock.txt يسجل مجموعة Linux/Python 3.12 المختبرة، ومنها توافق FastAPI المثبت في بيئة الاختبار.اعتماديات Windows الشرطية، ومنها pywin32، يتطلب تثبيتها والتحقق منها على الجهاز. لا تغيّر بيئة خدمة قائمة عميانيًا.

التفعيل يبدأ بحفظ المصدر المحلي كاملًا ومقارنته ودمج التغييرات في الخدمة القائمة، ثم اختبار مسارات Python وNode وentrypoint والتفويض والمهل والتعافي على Windows. لا يُستخدم reset ولا تُستبدل النسخة المحلية لمجرد اختلاف HEAD.

البرمجيات المختارة مجانية بموجب MIT؛ تشغيل نموذج عبر خدمة مدفوعة ليس مجانيًا تلقائيًا. لم يُثبت Ollama أو ينزّل نموذج لأن الطلب يتعلق بالقناة، ولا يوجد دليل أن المشروع يحتاج مشغل نموذج جديدًا.
