# اختيار أدوات الاستدعاء وضبط التكوين

تاريخ التحقق: 2026-10-05. هذه نتيجة بحث وتصميم، وليست إثبات تثبيت أو تشغيل على Windows.

## الاختيار

طبقة البروتوكول: الحزمة الرسمية `modelcontextprotocol/python-sdk` بترخيص MIT، داخل خادم RAIOS الحالي. تدعم العميل والخادم وstdio وStreamable HTTP. تُختار نسخة مستقرة متوافقة بعد مراجعة Python والاعتماديات المحلية؛ لا يُستخدم main أو latest في التشغيل.

طبقة تنفيذ الملفات والأوامر: إعادة استخدام مزوّد Desktop Commander المحلي المملوك الموجود في `scripts/ai-os/raios_mcp/desktop_commander_provider.py` بعد إصلاح حدود الانتظار والعزل والتعافي. المشروع الأصلي MIT. تشغيل هذه النسخة المحلية لا يتطلب خدمة الموصل المستضافة أو حصتها الشهرية، ولا يعني ذلك أن مسارها المحلي ثبت جاهزًا حاليًا.

طبقة اتخاذ قرار function calling عند الحاجة إلى نموذج مجاني محلي: Ollama (MIT) مع نموذج محلي يدعم tool calling وترخيص مناسب. Ollama يقترح استدعاء الدالة؛ RAIOS يتحقق من الصلاحيات وينفذ ويرجع النتيجة إلى النموذج. لا ينفذ Ollama أوامر النظام تلقائيًا بمجرد إخراج tool_call.

لا حاجة لإضافة وكيل مستقل الآن. Goose (Apache-2.0) خيار لو احتاج المشروع لاحقًا واجهة وكيل كاملة، لكنه سيكرر أجزاء من التنسيق الموجود إذا أُضيف دون حاجة مثبتة.

## معنى المجانية

النسخ التي تحمل MIT أو Apache-2.0 يمكن استخدامها وفق تراخيصها دون رسوم اشتراك للمكتبة. لا يمكن ضمان سياسات جميع الإصدارات والخدمات المستقبلية. التشغيل المحلي يتطلب موارد جهاز وكهرباء؛ واجهات النماذج المدفوعة تبقى مدفوعة. ترخيص أوزان النموذج مستقل عن ترخيص Ollama ويجب التحقق منه قبل الاختيار.

## ضبط التكوين ضمن مسار واحد

1. جمع المصدر المحلي الكامل وHEAD والاعتماديات والسياسة الفعلية ومطابقتها مع GitHub؛ الاحتفاظ بالتعديلات المحلية ثم دمجها مراجعةً بمراجعة. لا pull/reset أعمى.
2. اشتقاق إعلان الأدوات وفحص الجاهزية من سجل واحد ومن السياسة الفعلية؛ عدد ثابت 8 أو 9 ليس عقدًا صالحًا للتوسع. توافق أدوات العملاء الحالية مطلوب.
3. فحص مسبق لإصدار Python وNode، ومسارات executables وentrypoint، وإصدارات المزوّد، والمنافذ، والعنوان المحلي، والتفويض والنطاقات. المسارات تعتمد على الجذر المعيّن، لا على cwd أو اسم مستخدم ثابت.
4. فحص أدوات المزوّد عبر initialize وtools/list مع مهلة محددة. عرض حالة disabled/denied/unavailable لكل قدرة، بدل إعلانها جاهزة لمجرد وجود ملف.
5. إبقاء health مستقلًا عن بدء المزوّد والنموذج وGit. فشل أداة لا يسقط الخادم كله؛ تُعرض حالات transport_ready وexecution_ready بصورة منفصلة.
6. عميل loopback للقراءة يبقى للقراءة. منح الكتابة ترتبط بهوية ونطاق وlease وidempotency، ولا تُفتح بصلاحية wildcard.
7. تثبيت الإصدارات وملفات القفل، والتحقق من التوافق قبل الترقية، وحفظ الإعداد السابق وخطة رجوع، وتنقيح الأسرار من السجلات.
8. تطبيق اختبارات التحمل والأعطال الواردة في EXECUTION-CHANNEL-DESIGN.md على النسخة الموحدة، ثم اختبار Windows قبل إعلان اكتمال التكوين والتنفيذ.

## الأدلة والحدود الحالية

GitHub API أظهر التراخيص وحالة المشاريع غير المؤرشفة للمستودعات الأربعة في تاريخ التحقق. README الرسمي لـPython SDK يذكر stdio وStreamable HTTP. وثائق Ollama الرسمية تعرض tool calling واستدعاءات متوازية.

المصدر المحلي الكامل لم يُستخرج؛ get_diff يكشف التغييرات غير الملتزمة ولا يكشف محتوى الالتزام المحلي غير الموجود في GitHub كاملًا. القناة الحية لا تعرض أداة تنفيذ، وموصل الجهاز الآخر أبلغ نفاد الحصة. لذلك لم يُثبت تثبيت الحزمة أو إصلاح التكوين على الجهاز.
