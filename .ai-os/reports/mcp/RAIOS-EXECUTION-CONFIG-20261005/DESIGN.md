# تصميم ترقية قناة RAIOS التنفيذية — مسودة للمراجعة

التاريخ: 2026-10-05. الحالة: تصميم مقترح؛ لم يُنفّذ ولم يُختبر على الجهاز.

## الهدف والحقائق المثبتة

المطلوب تنفيذ العمليات المصرّح بها عبر قناة RAIOS القائمة، واستمرار استجابة القناة عند بطء الأدوات أو فشلها، مع سجل واضح لكل عملية. لا يكفي إعلان عدد أدوات أعلى لإثبات التنفيذ.

القناة الحية أعلنت ثماني أدوات قراءة ومراسلة وHEAD محليًا هو `dfc08e62a6392af53c9995e74278a5ba6d153a84`. نجحت قراءات عبر موصل RAIOS. المصدر الذي نُشرت عليه إصلاحات PR18 مختلف، ومساره `tool_execute_scoped_task` يقبل READ_ONLY فقط. التعديلات المحلية تشمل gateway/server والسياسة وسكربت التشغيل؛ يجب دمجها بعد استخراج مصدرها الكامل، وليس استبدالها بنسخة GitHub.

المرفق الجزئي يحتوي 127 مسار إيصالات رسائل غير متتبعة وينتهي مبتورًا؛ لا يحتوي تاريخ الالتزامات ولا يثبت سبب التعليق. لا يُحذف أي إيصال أو تعديل محلي ضمن الترقية.

في مزوّد Desktop Commander الموجود بالمصدر المفحوص: قفل تسلسلي بلا مهلة اكتساب، وطابور ردود غير محدود، وكتابة stdin قد تحجب، ومهلة الرد لا تضمن استعادة عملية المزوّد. هذه مخاطر مصدرية؛ ليست إثباتًا منفردًا لسبب عطل Windows السابق.

## البدائل والاختيار المقترح

1. ترقية الخادم والمزوّد الحاليين وربط التنفيذ بعقود التفويض والمهام القائمة: أقل تغيير تشغيلي، يحافظ على العملاء والإيصالات؛ وهو الاختيار المقترح.
2. نقل التنفيذ كله إلى خدمة جديدة: يوفر عزلًا إضافيًا لكنه يكرر قناة التحكم والسجل، ويزيد مخاطر التشغيل؛ لا يُقترح.
3. الاكتفاء بإضافة اسم أداة التنفيذ إلى tools/list: قليل العمل لكنه لا يعالج التعليق أو صلاحيات التنفيذ أو النتائج المجهولة؛ لا يحقق الطلب.

## العقود والتفويض

تبقى أدوات القراءة والمراسلة متوافقة، ويُرقّى مسار التنفيذ الموجود. تُكتشف أدوات المزوّد المملوك محليًا وتُطابق مع سياسة صريحة لكل عملية ونطاق؛ أي أداة غير معروفة أو غير مصرح بها تعيد خطأ منظمًا. لا تُمنح صلاحيات تنفيذ لعميل LOOPBACK_READ تلقائيًا.

لكل تنفيذ هوية مصادق عليها، operation، arguments، نطاق الموارد، correlation_id، ومفتاح idempotency. الكتابة تتطلب منحة مناسبة وlease صالحًا مع fence، وفحص النطاق قبل العمل. لا يمنح اكتشاف الأداة أو امتلاك lease صلاحية إضافية. يشمل الدعم جميع الأدوات المطلوبة التي يمكن للمزوّد تشغيلها ضمن هذه العقود، مع بيان الأدوات المحجوبة وأسبابها.

تُستخدم مكونات command-fabric والمهام والإيصالات القائمة، ولا يُنشأ سجل مهام أو ناقل رسائل موازٍ. يجب فحص ذرية اكتساب lease في التنفيذ الحالي تحت التزامن قبل الاعتماد عليه لمنع الكتابة المتعارضة.

## الاستجابة والعزل

تكون فحوص الصحة خفيفة ومستقلة عن Git والمزوّد وسجل التدقيق. تُطبّق حدود منفصلة لطلبات HTTP، وجلسات SSE، والمهام، وأحجام الرسائل والنتائج؛ امتلاء الحدود يعيد BUSY مع معرّف تتبع خلال مهلة قصيرة بدل الانتظار المفتوح.

تشمل المهلة اتصال العميل وقراءة جسم الطلب واكتساب القفل وبدء المزوّد والكتابة والقراءة وتنفيذ العملية. لا يكفي تغليف انتظار الرد وحده. تُعزل أعمال المزوّد عن خيوط خدمة HTTP، مع طابور محدود وربط الرد بمعرف الطلب وجيل العملية، وحفظ الردود المتداخلة دون إسقاطها.

المهام الطويلة تُقبل بمعرف تشغيل وحالة قابلة للاستعلام والإلغاء عبر البنية القائمة. يلزم إثبات أن القتل ينهي شجرة عمليات Windows الفعلية؛ لا يُدّعى ذلك اعتمادًا على إنهاء العملية الأم فقط.

## الفشل والتعافي

يُغلق المزوّد المعطوب ويُعاد تشغيله بحدود وتراجع زمني مضبوط. تبقى واجهة الصحة والقراءة المحلية متاحة أثناء التعافي. تُفحص هوية PID ووقت إنشائه ومسار البرنامج قبل إيقافه، لمنع قتل عملية أعيد استخدام رقمها.

الأخطاء تعود بصيغة MCP منظمة مع code وcorrelation_id دون أسرار. عند انتهاء المهلة بعد إرسال عملية كتابة، تكون النتيجة UNKNOWN_OUTCOME إلى أن تُطابق مع أثرها؛ لا تُعاد الكتابة تلقائيًا. مفتاح idempotency ثابت وعملية حجزه ذرية ويستمر أثره بعد إعادة التشغيل. القراءة فقط يمكن إعادة محاولتها ضمن ميزانية مهلة معلنة.

إذا تعذر تثبيت نية التنفيذ وسجلها المطلوب قبل الكتابة، تُرفض الكتابة. وإذا فشل حفظ النتيجة بعد حدوث الأثر، يُعلن ذلك بوضوح ويُحفظ مسار المصالحة؛ لا يُعرض نجاح نظيف أو فشل يوحي بإمكان التكرار الآمن.

## التحقق المطلوب قبل إعلان الجاهزية

- عقد tools/list وhealth والسياسة متطابق؛ كل أداة مطلوبة لها إثبات تشغيل أو سبب حجب واضح.
- تنفيذ قراءة وكتابة محدودة في مجلد اختبار مصرح به، وإثبات رفض هوية بلا صلاحيات ونطاق خارج المنحة.
- تعليق مزوّد وفقد رد وموت عملية وامتلاء الطابور: رد منظم ضمن المهلة، وصحة مستقلة مستهدفة خلال ثانيتين في اختبار Windows المحلي المحدد.
- طلبات متزامنة وردود متداخلة وعميل HTTP بطيء ورسالة كبيرة وانقطاع SSE: حدود الذاكرة والعمليات والخيوط لا تتجاوز القيم المضبوطة، ويظل التعافي ممكنًا.
- إعادة طلب كتابة بالمفتاح نفسه بعد timeout وإعادة تشغيل: لا تتكرر العملية، أو تبقى النتيجة المجهولة معلنة حتى المصالحة.
- JSON تالف وفشل ملفات وامتلاء القرص وفشل التدقيق: أخطاء منظمة دون تسريب أسرار ودون نجاح زائف.
- تجربة Windows على النسخة الموحدة، ثم تسجيل HEAD وهوية العملية والنتائج والإيصالات وخطة الرجوع. نجاح اختبارات Linux وحده لا يثبت تشغيل الجهاز.

## ترتيب الترقية وما يلزم لإتمامها

أولًا حفظ ومقارنة المصدر المحلي الكامل مع المصدر المنشور؛ ثانيًا تثبيت عقود التنفيذ والمهل والحدود؛ ثالثًا ترقية المزوّد والخادم ومسار التفويض؛ رابعًا اختبارات الأعطال والتزامن؛ خامسًا نشر مراجَع وتجربة Windows محدودة ثم تفعيل تدريجي.

النسخة المحلية الكاملة وإثبات تشغيل المزوّد وصلاحيات هوية التنفيذ لم تتوفر بعد. موصل الجهاز الآخر أبلغ نفاد حصته، وموصل RAIOS الحي لا يعرض أداة تنفيذ؛ لذلك لا يمكن الادعاء حاليًا بإصلاح الجهاز أو تنفيذ أوامر عليه. هذه المسودة لا تغيّر الخدمة الحية أو سياساتها.
